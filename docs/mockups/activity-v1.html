给 human 一个对称的「有一个队列在等我」入口（Human/Agent 同构）。所有行都是 listActivity 投影，UI 从不写 read 状态。

分级（salience，内部词不上界面）

  • directed（@我 / DM / task / agent 启动失败）→ 左侧墨色 rail，永远进，置顶。
  • ambient（关注的 thread / 「所有消息」channel 的未读）→ 无 rail、稍弱。

清除（read-driven，降解为 observe）

  • 打开 / 跳源 → 推 cursor / 置 notification read。
  • Mark as read = hover 才显的 ✓ icon，不是常驻 Done；扫一眼 / hover ≠ 读。
  • task 行 无 Mark as read：主操作「去处理」，离开 Activity 锚在 task 状态（resolve-cleared）。
  • 顶部「全部标已读」= 批量 observe（task 除外）。

去重

  • per-(viewer, message)：@我那条只显示成 mention，不再作 ambient 未读重复出现。

类型筛选（shiki）

  • 单选一排 chip，默认 All；纯客户端切片 listActivity，不发新请求。
  • 四个固定 chip：All / Mentions=mention · Tasks=task · Threads=在 thread 里。不逐 kind 铺开（shiki：避免噪音）。
  • chip 是 utility：选中走 lime（选中色），chip 本身不染语义 hue（Tasks≠黄、Threads≠粉），不偷 item 的响度。

hue 锁（forza6）

  • 粉 = channel# / unread
  • 黄 = task 身份
  • 橙 = in_review
  • lime = 选中
  • utility（hover / mark icon / 分隔）一律走墨 / 中性。
