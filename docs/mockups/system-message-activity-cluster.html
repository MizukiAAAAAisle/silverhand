PR-10 — Activity Cluster (mockup)

把 task_* / session_cleared / rename 这类高频低权重事件， 从"独立消息行"降级为"活动注释段"（Slack-style muted activity narration）。规则： clusterable subtype + 流相邻 + 5min gap 自然成段，再按 unread boundary 二次切分。 视觉：去头像、对齐到正文 content column、整组挂左侧 1px subtle rail、组内行距压缩、组外加 7px gap。 左侧是当前 feature/v1-polish PR-9 后的样子，右侧是 PR-10 后的样子。

场景 3 — unread boundary 切 cluster

activity run 内部跨已读/未读边界时，强制切两段。理由：cluster 是视觉块，不切的话用户会把"是否已读"误归到整组上。切完之后两段 cluster 各自独立闭合，read cursor 移动只会改变 unread UI，不会让 cluster 边界飘。

分类决策（与 @Cindy 收敛）

  • 进 cluster（low-priority activity）：task_create、task_claim、task_unclaim、task_status、session_cleared、rename
  • 不进 cluster（信息块保留分量）：schedule_fire、thread_anchor、child_context、channel_context、thread_summary、mention_cc、onboarding

Grouping algorithm

  • messages → activity runs (subtype/相邻/5min gap) → split by unread boundary → render
  • 不要求同 task / 不要求同 actor
  • 纯函数实现：groupMessages(messages): Array<MessageItem | ActivityCluster>，cluster id activity-cluster:${first.id}:${last.id}:${count} 稳定 reconciliation
  • 实现层级：MessageList / MessageStream（只有列表层能看到相邻消息）

视觉规范

  • 整组对齐到正文 content column（跳过 avatar lane）
  • 整组左侧 1px border-subtle rail + padding-left: 10px
  • 组外 margin: 7px（上下），跟正文断开节奏
  • 组内 padding: 2px 0（紧贴），多条 audit row 视觉聚拢成一段
  • 背景默认透明 — 不上 bg tint，避免又变成卡片化
  • 单条降权：actor → text-secondary（去 font-medium）；chip → 透明 bg + subtle border；status pill → 透明 bg + 同色 outline；status dot → 8px 缩成 6px
