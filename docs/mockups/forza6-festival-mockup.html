Hard cut, not gradient

Chrome ↔ chat boundary uses an 8px gap (--frame-padding) exposing --bg-app deep teal — exactly per Cindy's review point #4. There is no saturation gradient; the chat panel is a flat opaque white rectangle.

What's intentionally on screen

  • Black structural strips (titlebar tint, member-strip, now-playing, segment-control bg) → review #1
  • Lime focus outline on NavRail active icon + popover border → review #1
  • Hot-magenta selected channel row (energy CTA-style)
  • Cyan link + cyan running-tool status (3rd-tier accent)
  • Yellow metadata text (3,100 / 6,000 XP, 07 LV · 96%, NOW @ name) → demonstrates --text-on-dark-pop use; let shiki decide if this earns a global token
  • Royal purple is on screen ONCE (Cindy DM avatar) — not promoted to a global token (review #5)
  • Code island has its own subtle triangle texture (lime tint) — counter-example to "one-pattern-fits-all" (review #2)
  • Display-caps font on every chrome label, every section header, status pills — --font-display earning its keep

Open trade-offs

  • Chat read-area font / size / weight — using app default. Forza-style display caps would be wrong for body copy.
  • Dark mode not in this mockup (deferred per Cindy).
  • Loading state, toast variants, modal overlays not shown — extension once style is locked.
