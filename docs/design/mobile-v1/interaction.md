# Silverhand 手机交互设计 v1

状态：提案，待 Shiki 确认。任务 #2667。本文与可点击原型共同描述目标交互，不代表功能已经实现，也不改变现有服务端权限。

打开同目录 [index.html](./index.html) 可离线体验；不访问真实账号、服务器或设备。原型中的人名、消息和状态均为演示数据。

## 1. 产品结构：Chats / Activity / Tasks / More

按 Shiki 本轮反馈，底部四个位置为 **Chats / Activity / Tasks / More**。前三个是内容主区；**More 是菜单按钮，不是第四个内容 Tab，也不创建第四套导航历史**。

| 底部入口 | 职责                                           | 状态                             |
| -------- | ---------------------------------------------- | -------------------------------- |
| Chats    | 频道、私聊、线程、工作区范围、搜索、收藏与归档 | 独立浏览栈，现有未读投影产生小点 |
| Activity | 跨工作区注意力队列、@我的与线程上下文          | 独立浏览栈，有未处理项时小点     |
| Tasks    | 可见任务列表、筛选、详情、来源                 | 独立浏览栈，不把全部待办当未读   |
| More     | 向上弹出 Members / Computers / Settings        | 菜单开关，无未读角标，不切换内容 |

### More 的明确行为

- 点 More，在按钮上方出现锚定的小型 popover：**Members / Computers / Settings** 三项，顺序固定；不是从底部盖满的 sheet，也不是“更多功能”列表页。
- 展开时底层页面、选中的主 Tab、滚动与草稿完全不变。点空白、再次点 More 或按 Escape 关闭；关闭后焦点回 More。
- 点一项后先关菜单，再把目标页面压入当前主区的来源栈。顶部返回到打开菜单前的页面；下方仍选中原主 Tab，More 不伪装成第四个选中内容。
- 例如 Chats/频道 → More → Members → Cindy → 私聊，逐层返回到 Cindy、Members、原频道。Tasks/任务详情 → More → Settings，返回仍是该任务详情。
- 点击另一个主 Tab 关闭菜单并恢复该主区自己的浏览栈。再进入先前主区，恢复其当前页（包括正在浏览的 Members/Settings）；重复点当前主 Tab 回该主区根页。
- 键盘显示时导航让位于输入；不是用户开着键盘还要把 popover 塞进很小的剩余空间。收起键盘后 More 位置稳定。
- Members 内含 Agent / 人员；Computers 仍可从 Agent 详情的所属计算机直达。Settings 汇总账号、外观、server 连接和退出。头像仅作本人资料快捷入口，不再承担另一套管理导航。

原提案把 Members 直接放底栏；本轮改为统一 More，减少顶部头像承担的隐含入口，并把三类管理页集中到稳定位置。信息实体和权限不随入口变动。

底部导航在主区浏览栈内保持可达；系统键盘出现时让位于输入。媒体预览、首次连接、登录和阻断认证页面不显示底栏。根列表重复点击不清筛选或清未读。

## 2. 范围：没有全局「当前工作区」

这是现有实体模型的约束，不是视觉偏好。私聊没有 workspace；动态跨工作区；成员和计算机属于服务器范围。

- 会话根页默认「全部」，范围选择器可选某个普通工作区、Agent 空间或「私聊」。选工作区只过滤会话列表，不重置任务、动态、成员。
- 根页默认分组：收藏会话 → 私聊 → 工作区 → Agent 空间。收藏是同一个会话的快捷位置，不复制消息、草稿或未读。
- 工作区子页提供频道列表、成员、资料与有权限的管理操作。普通工作区与 Agent 空间有清楚标识，不把归属差异藏在名称中。
- 任务有自己的范围筛选，显示当前范围。来自会话的「任务」入口只显示该会话关联的任务，并标注范围；DM 只按 conversation ID 过滤，不虚构 workspace。
- 全局搜索默认搜索当前服务器可访问的会话内容。会话内搜索显式预选该会话；工作区、发送者等筛选标签可见且可清除。DM 搜索不能继承上一次工作区筛选。
- Settings 始终展示当前账号与 server 域名。server 是身份/数据隔离边界，切换它不是切工作区。

## 3. 导航树与返回模型

[查看完整导航图](./navigation.svg)。

```text
连接 server → 登录 / 注册 → Chats / Activity / Tasks + More
  会话 → 工作区频道列表 → 会话 → 线程
       → 私聊（含首条发送前的草稿页）→ 线程
       → 搜索 / 收藏 / 归档 → 命中会话或线程
  动态 → 消息上下文 → 线程 / 任务引用 / 成员
  任务 → 任务详情 → 来源会话或线程
  More ↑ popover
       → Members → Agent / 人员详情 → 私聊 / Agent 空间 / 计算机详情
       → Computers → 远程计算机详情
       → Settings → 账号 / 外观 / 切换 server / 退出
```

**三个内容主区各保留自己的导航栈，More 中的页面进入调用方栈。打开目标时保留“我从哪里来”，不突然切走另一个 Tab。**

| 入口               | 去向与顶部标题                             | 返回位置                                                      |
| ------------------ | ------------------------------------------ | ------------------------------------------------------------- |
| 会话列表点频道     | 频道内容；标题下显示工作区                 | 原列表、原筛选、原滚动位置                                    |
| 频道点线程回复     | 全屏线程；顶部显示所属频道，根消息可展开   | 频道原消息锚点                                                |
| 动态点线程消息     | 动态栈内的线程上下文                       | 原动态列表，不跳到会话首页                                    |
| 搜索点命中         | 定位并高亮消息，线程命中进入线程           | 保留关键词、筛选和结果滚动位置                                |
| 任务点来源         | 来源会话/线程中的源消息                    | 原任务详情                                                    |
| 成员点发消息       | 当前来源栈内私聊；尚无 pair 时先显示草稿页 | 原成员详情；未发消息不创建空私聊                              |
| 消息点任务引用     | 当前栈内任务详情                           | 原消息位置，不重置任务 Tab 的筛选                             |
| More 打开 Settings | 全屏设置，保留底层 Tab 上下文              | 关闭/返回原页面                                               |
| 外部深链接         | 登录后校验权限，再进入最小合法父栈         | 线程→所属会话→会话根；任务→任务根；成员→Members 列表→Chats 根 |

返回按钮与 iOS 左缘返回手势一致。弹层先关闭弹层，键盘先按系统行为收起；不能用手势绕过未保存表单确认。线程不嵌套线程：线程内回复仍属于同一根消息。

跳转引用最多追加一个详情层；反复打开同一目标复用现有层，避免 A→B→A 无限压栈。外部链接或无历史时绝不返回空白页。跨 workspace 的链接保留实际归属，不悄悄改变其他 Tab 的范围。

### 状态保存

| 状态                           | 切 Tab / 打开详情 / 正常前后台     | 退出 / 切 server / 认证失效            |
| ------------------------------ | ---------------------------------- | -------------------------------------- |
| 页面栈、列表锚点、搜索词、筛选 | 同身份内保留                       | 全部清除                               |
| 输入草稿                       | 按会话+线程根保存，回原处继续      | 用户主动离开前提示丢弃；强制失效时清除 |
| 正在发送的身份                 | 保留原 sendAttempt，补读/重试复用  | 不跨身份恢复或自动重发                 |
| 未读与动态状态                 | 服务端现有 read-model 为权威       | 新身份重新加载                         |
| 表单修改                       | 页面内保留；离开询问保留编辑或放弃 | 不传入新身份                           |

同一会话可能从不同 Tab 打开，但草稿、发送去重和已读是同一份逻辑状态，不能创建多套。进程被 OS 终止后，目前不承诺恢复内存草稿；若要承诺另立持久化草稿需求。原型只演示当前打开会话中的内存状态。

## 4. 会话列表与创建

根页顶部：账号头像、标题「会话」、搜索、新建。第二行是可见的范围选择器。列表行：身份图标、标题、归属、末条消息摘要、时间、现有未读标记；Agent 执行状态用独立文字/图标，不混成未读数字。

「新建」动作表：发私聊 / 新建频道 / 新建工作区。创建频道必须选择归属工作区，不能从模糊“当前工作区”推断；创建私聊选择人或 Agent。表单是全屏页面，具有取消和创建按钮，提交中避免重复创建，失败保留输入。

工作区与频道管理：标题打开详情；有权管理者可编辑资料、成员、归档/恢复。删除与退出有独立确认，列明影响；服务器返回无权限或依赖阻止时解释原因，不显示虚假成功。归档会话在归档列表查找，不占默认列表；搜索/链接能定位时显示归档状态。

## 5. 消息、线程与输入

会话标题展示清楚的身份：频道显示工作区+频道；私聊显示对方，不出现 workspace 管理或添加群成员入口。标题下的状态条显示断网、正在重连、无发送权限或 Agent 错误，不能盖住输入。

- 文本：多行输入，发送按钮始终明确；手机 Return 换行，硬件键盘 Command+Return 发送，中文组词期间不触发发送。
- @：输入区上方候选列表，显示人/Agent 身份与真实可选范围；选中插入结构化引用，不靠拼接名字制造 mention。
- 消息状态：发送中 / 待确认 / 失败。失败重试复用原发送身份；超时不等于未送达，优先补读确认，避免双发。离线不承诺自动排队或自动发出。
- 流式更新不把正在读历史的用户拉回底部。位于底部才跟随；离底部时提供「N 条新消息 / 回到最新」入口，滚动不误清不可见内容的未读。
- 长按消息打开动作表：回复线程、表情、复制、收藏、复制链接；本人消息才出现可用的编辑/删除。附件相关操作按实现阶段和权限显示。触控长按必须与文本选择协调，代码块提供独立复制按钮。
- 线程用完整页面，顶部返回所属上下文、显示频道名，根消息摘要固定可展开；底部提示「回复这个线程」。长文根消息不占满首屏。关注/取消关注保持现有语义。
- 会话详情提供成员、线程索引、相关任务、附件索引、搜索、通知/收藏及管理入口；DM 使用双方详情，不出现群管理。
- 手机不同时显示桌面主/副两栏。打开会话链接、线程或任务是压栈，关闭回原处；横屏也不自动复制桌面三栏。

## 6. 动态：需要我关注的消息

保持现有 Activity 合同：跨工作区，全部 / @我的 / 线程筛选；顺序使用服务端结果，不由手机重新计算优先级。

动态展示来源→主题→触发消息。点击进具体消息/线程并按现有规则观察；行尾「处理」按钮可显式清除，无需依赖 hover 或隐蔽手势。保留列表中的附近位置，已处理项消失后不跳顶。空态为「暂时没有需要关注的消息」，不要写“所有任务已完成”。

不把 in_review 任务状态镜像塞进动态，不新增 APNs、后台收件通知承诺。任务需要关注的规则若未来变成独立事件，另行设计。

## 7. 任务：列表优先，详情完整

手机默认按状态分组的纵向列表，不要求横向拖动五列看板。顶部范围与筛选：归属、状态、负责人、创建者；打开筛选抽屉后“应用”一次生效，取消不改变列表。默认沿用既有可见范围，不擅自改成“只看分配给我”。

任务详情是全屏页面：编号、标题、状态、负责人、归属、正文、来源消息。长正文可滚动，状态与负责人通过明确选择器修改，不依赖拖拽。标记完成与关闭、领取与指派按既有权限分别呈现；提交失败回退并保留用户选择上下文。

从频道进入关联任务：顶部标明频道范围，可返回频道；从 DM 进入只显示该 pair 的任务，无 workspace 下拉伪入口。新建任务须明确实际容器；无创建权限时显示解释，不在服务端拒绝后才揭示归属。

任务列表的样例数据和编辑在原型里仅为模拟，不承诺手机已支持全部写操作。

## 8. 成员、Agent 与计算机

成员根页「Agent / 人员」分段，支持搜索。Agent 卡片显示名称、runtime、所属计算机及在线/忙碌/错误状态；人类成员不显示 runtime。详情先给常用操作「发消息」「打开 Agent 空间」，再给运行状态与配置。

- 普通查看者只看被允许的数据；编辑、启停、配置、删除等动作严格使用服务端和现有能力判断。
- 新建/配置 Agent 是向选定的远程计算机下达操作，不在手机安装 runtime。先选可用 computer，缺少权限/离线时说明原因；不可把手机当默认 host。
- 计算机入口：More → Computers；Agent 详情 → 所属计算机。详情显示在线状态和所属 Agent，操作对象始终写出计算机名。
- user_invite 与 app_install 保留不同操作集；本人远程 app_install 可撤销，手机不提供“刷新本机 host token”；非本人/system/已撤销对象不能套用管理权限。
- 远程停止/撤销必须确认影响。界面不提供“打开本机终端/文件夹”这样的假入口；能复制的远程路径标为远程路径。

## 9. 附件与预览：完整设计，分阶段交付

输入框「＋」：照片/视频、文件（未来实现后开放）；采用系统选择器，不默认索取整个相册访问。选中后显示附件队列、大小、上传进度、失败重试、移除；超限在发送前说明，仍以服务器限制为准。发送正文与附件结果保持现有消息合同，不假设上传即发消息。

图片/视频：全屏预览，可缩放、关闭回原消息；文件：类型/大小/下载状态，系统分享或保存。HTML 等主动内容继续走既有安全预览约束，不把第三方页面接入可信原生桥接。下载失败留在详情，不伪造系统保存成功。

本轮实现能力尚不含上传/保存/图片剪贴板。生产中未就绪操作隐藏或明确标注不可用；设计原型可以预演，但点击时标注「后续能力」，不能静默模拟真实上传。

## 10. 账号、连接与异常

More → Settings：当前头像/姓名、server 域名、账号、外观、连接设置、退出；Computers 是 More 中的并列入口。账号只编辑自己；外观继承既有主题，视觉细化另评，不强行统一桌面与手机的信息密度。

| 情况                  | 交互结果                                                         | 保留/清理                                    |
| --------------------- | ---------------------------------------------------------------- | -------------------------------------------- |
| 首次启动              | server 地址页→校验→登录；注册是否可用由 server 决定              | 未验证成功不提交 origin                      |
| 地址/TLS/响应错误     | 表单内错误、修正重试；不提供绕过 TLS                             | 保留已登录旧 server                          |
| 切 server             | 先提示正在发送/草稿影响；测试候选成功后提交；进入新 server 登录  | 提交前失败不动旧会话；提交后清所有旧身份状态 |
| 退出                  | 提示本机草稿影响，确认后退出，保留可重新登录的 server 地址       | 清凭据、查询、导航、浏览器状态               |
| 正常回前台            | 顶部轻量“正在恢复”；原界面保持，重验并补读                       | 保留草稿、滚动锚点与 sendAttempt             |
| 暂时断网/503          | 顶部离线条、重试；已加载内容可读                                 | 不转登录、不清草稿、不伪报发送成功           |
| 401/撤销/改密失效     | 阻断认证页，要求重新登录                                         | 原账号私有状态失效，不传入新账号             |
| server/app 版本不兼容 | 区分“更新 App”与“更新 server”，提供连接设置                      | 不显示成普通密码错误                         |
| 深链接无权限/已删除   | “内容不可访问”，返回原处或合法根页                               | 不回退展示旧缓存内容                         |
| 系统杀进程            | 冷启动恢复原生会话，重新校验；有明确草稿恢复能力前不承诺内存恢复 | 不伪装成连续前后台                           |

草稿丢弃确认只用于用户主动退出/切 server 等破坏性动作，普通返回/切 Tab 不弹窗打断。服务端强制失效不能让“取消”继续使用旧身份。

## 11. 触屏与无障碍规格

最小点击区按 44×44pt 设计；文本支持系统字号和 VoiceOver。图标有可读标签，状态同时用文字和颜色。顶部避开刘海/灵动岛，底部按 safe area 布局；键盘升起只压缩消息视口，不能遮挡发送按钮；输入框正文至少 16px，避免网页输入缩放。

左右返回手势不与横向看板拖动冲突；滑动动作均有显式菜单替代。减少动态效果设置下禁用非必要位移动画。网络 loading 使用骨架或局部状态，长操作明确允许取消/返回。原型不代表最终品牌色或动效批准。

## 12. 原型走查与实施验收

原型包含三个主区和 More popover、工作区范围、频道→线程、动态→来源→返回、搜索→定位→返回、任务详情/来源、成员→私聊、More→Members/Computers/Settings、连接/登录、离线与会话失效场景。所有数据都是本地演示；附件弹出后续能力说明。右侧场景按钮用于评审，不是产品内调试 UI。

按以下顺序评审：

1. 从会话进入频道，写一段草稿，切任务再切回；进入线程后返回频道，区分两个输入目标。
2. 动态进入线程，再返回动态；搜索命中返回结果，确认没有被带去错误 Tab。
3. 切会话 workspace 筛选，检查任务/动态/成员没有被全局切换；查看 DM 不出现虚构工作区。
4. 从任务进来源再返回；从成员发首条私聊，确认“只是打开”不创建服务端对象（原型只演示）。
5. 走离线、恢复、无权限、server 测试失败和会话失效。核对原状态何时保留、何时清理。
6. 看计算机与附件入口，确认远程操作身份清楚，未交付能力不被当成成功。

设计确认后，实施分三段：A 三个主区、More 与导航/返回/状态恢复；B 会话输入、线程、动态、任务/成员的触屏页面；C 附件系统桥接与完整管理表单。每段做真机键盘、安全区域、同账号前后台、未授权入口和 Desktop 回归。TestFlight 在这些通过后进行。

## 14. 桌面与手机如何复用

### 推荐：共享状态和内容，两种外壳

当前原型使用 HTML/CSS。建议正式手机底栏与 More popover 也用 React/Web 实现，仍在 Capacitor 的 WKWebView 内。Capacitor 提供原生接入能力，不会自动把 React DOM 转成 UIKit。真正的 UIKit Tab Bar 是可选方案，需要另做原生容器与 Web 导航的接口；它不是此次选 Capacitor 就自动获得的控件。[Capacitor 原生扩展](https://capacitorjs.com/docs/ios/custom-code)

| 层             | 共享或区分                      | 例子                                                       |
| -------------- | ------------------------------- | ---------------------------------------------------------- |
| 业务与会话     | 共享，只有一份权威              | 数据查询、权限、消息归并、未读、草稿、发送身份、任务动作   |
| 内容组件       | 结构相近则共享，CSS 响应式      | 消息正文、头像、状态标记、附件卡片、资料字段               |
| 交互组件       | 共用动作模型，分别呈现          | 桌面 hover 菜单 / 手机长按菜单；桌面 dialog / 手机全屏表单 |
| 导航和布局外壳 | DesktopShell / MobileShell 分开 | 桌面 NavRail+侧栏+副栏；手机底栏+单页栈+More               |
| 系统能力       | 平台适配器提供                  | iOS Keychain、选择文件、分享、键盘通知；Desktop 本机能力   |

目标模块边界（是拟议实现分工，不是本轮重构）：

- `packages/client` 保留平台契约、会话与传输语义；不放 React 导航。
- `packages/app-ui` 的 feature hooks/动作模型与内容组件继续共用；新增明确的 desktop/mobile shell，而不是复制整个 App。
- app-ui 导航层保存领域目标与来源：conversation/thread/task/member 等。Desktop 把目标映射到主副栏，Mobile 把目标映射到页面栈；两边不维护两套实体 ID、权限或深链接解析规则。
- QueryClient、草稿和发送状态位于外壳之上，不能因为切 breakpoint 或换外壳而被卸载清空；同一时刻只挂载一套外壳，不用 CSS 隐藏两套仍在运行的树。
- `apps/ios` 只负责 Capacitor 容器、Swift 桥接与平台装配；共享包不直接 import Capacitor。Desktop 继续装配自己的能力，不因变窄就失去本机能力。

### 响应式与分开写的边界

容器尺寸决定信息布局，输入能力影响交互，平台契约决定哪些动作存在。这三个维度分开：窄桌面可采用 compact shell；iPad 足够宽可采用分栏，但仍没有 Desktop host 能力。宽度阈值按最小可读列宽验证，不以 iPhone 型号或 user-agent 列表决定。

消息文字、表单列数、列表行密度、间距用 CSS/container query 调整。侧栏与底栏、线程副栏与线程页面、看板列与纵向任务列表属于不同结构，应单独组件，底下的 query/command 共享。不要在每个业务组件散布 isMobile 条件。

### 原生底栏的取舍

原生 UIKit 外壳能获得系统原生控件行为与随 OS 更新的呈现，这是它真实的优势。代价是需要桥接 Tab 选择、返回路径、More 展开、键盘与 safe-area、深链接和前后台；必须指定一个导航权威，不能 Swift 与 React 各保留互相冲突的路由状态。

当前更适合 React 导航：整套业务 UI 已是 DOM、用户指定了定制 More popover、未来窄桌面也可复用。系统照片/文件选择、分享等依旧用原生，不为了导航统一而模拟系统权限或文件访问。若后续明确要求原生 Tab Bar 的系统质感，再独立评估原生外壳；这不要求重写共享业务逻辑。

### 已确认约束：统一 navigate（Shiki，2026-09-28）

调用方只表达业务目标，打开与返回统一交给导航层。示意：

```ts
navigate({ kind: 'thread', conversationId, rootMessageId });
navigate({ kind: 'attachments', conversationId });
navigate({ kind: 'conversation-settings', conversationId });
navigateBack();
```

目标携带真实实体坐标，不携带 `openSidePanel`、`mobilePage` 等布局指令。频道和 DM 使用真实 placement，不为 DM 补造 workspace。搜索、动态、任务来源和消息链接解析后都进入这个入口，导航层统一记录来源及返回关系。DesktopShell 将目标投影为面板，MobileShell 将其投影为全屏页面；返回同样不由内容组件猜测是关闭侧栏还是退一页。

实施时先核并收敛现有 `router.ts`，不叠加一套平行 mobile router，不让 URL、面板选择与手机页面栈各自成为权威。具体 API 类型在核实现有路由后定稿，上述代码只说明调用语义。数据请求、权限判断、草稿/发送状态不迁入 navigate；导航只消费必要的会话边界和目标可用性结果。局部菜单展开、表单输入、列表筛选也不全部塞入全局导航。

这项架构约束已获确认，不代表其余交互细节或生产 UI 实施已全部获批。
