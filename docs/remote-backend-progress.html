Remote Backend · 进度看板

Silverhand 从「Electron 单机自用」走向「one backend codebase · one wire protocol · multiple deployment adapters」终态的工作清单。 每张卡片是一个 Stage / Phase 级单元（不是 commit 级），按状态分类，按依赖顺序成组。 终态约束已 lock 在 docs/daemon-server-link-flow.html（Panel 3 + 底部矩阵），本文档不复述，只跟踪进度。 整体路径分两个 milestone：M1 = final-form 语义完成 + backend 仍 embedded 跑在 desktop； M2 = backend 可随时部署到云上。这期目标 = M1。

Milestone 1 — Final-form 语义完成（已达成）

✅ 达成

M1 已达成（2026-05-30）：协议 / daemon / materialization / data-plane 模型按 R1-R4 终态正确实现； backend 仍通过 adapter 跑在本地（embedded in Electron main），不要求云部署形态成熟。 换句话说：代码长得已经像 standalone，但实际部署还是 embedded，「切到 standalone」是 deployment 动作而非代码改造。

包含：Foundations（已 done）· D3 desktop daemon lifecycle 全套 · D4.a/b/c/d/e（含 create-agent materialize intent + daemon 成为唯一 host-local path 权威）· D5.a（R4 envelope unification）· sticky host ownership / no auto migration。
不包含：production deploy infra / 容器化 / 云端 TLS / observability shipping / 多用户云端 auth 加固 / cloud soak。

Milestone 2 — Backend 可随时部署到云上

LATER

M1 完成后，backend 才有资格出门——把这份 codebase 拿到云上 host，多用户从公网接进来， 各自的 desktop daemon 通过 outbound WSS 接入同一个 backend。 目标是 production deploy infra 成熟，不再做协议/语义层改动。

包含：Docker / container 镜像 · 反向代理 & TLS · 可观测（log shipping / metrics / alarms） · Auth 加固（email verification / 2FA / password reset） · 备份 / migration 工具 · cloud soak gate · T1 内的 blob remote 中转 / driver template 分发 / workspace path remote 语义。
不包含：sandbox host / web client / mobile push / 横向扩展——那些是 T3 V2+。

T0Stage D5 · R4 envelope unification

R4 drift（D5.a 已闭合）：D5.a 之前，embedded 模式 daemon ↔ backend 走 HostClient Unix socket IPC subscribe，暴露的是一套 daemon RPC / subscribe API，不是 outbound frame envelope 的 adapter——「one wire protocol」承诺当时只是嘴上的。 D5.a 把这条统一掉：embedded + standalone 经同一 outbound frame envelope（仅 transport 不同），backend formal path 不再 import HostClient。D5 只做 transport/envelope 统一，不承载 materialize 业务语义。
